# Four-tab discovery implementation plan

**Goal:** Food, Drinks, Deals and Settings with visible searchable places and useful closing-time information.
**Architecture:** Shared directory cards use pure Newburyport hours/deal helpers and structured source-backed drink profiles. Existing recommendation, calendar and management routes remain available.
**Tech Stack:** Next.js App Router, React, TypeScript, Neon.
**Spec:** User-approved four-tab design and closing-time additions, November 9 2026.

## Constraints
- No invented prices or hours. Distinguish venue hours from unverified bar hours.
- No production data writes during implementation. Additive profile migration is prepared separately.
- Retain blue theme, installed logo, deals calendar and existing URLs.

## Tasks
- [x] Shared venue status: New York timezone, overnight previous day, exclusive close, final-hour badge, unknown vs closed, next known opening. Test boundary and DST cases.
- [x] Drink profiles: validated ranges, source/check date/coverage, editable form and optional JSONB persistence. Curated verified Poynt fallback. Test invalid inputs; preserve old schema reads.
- [x] Food/Drinks visible directories: loading/error/empty states, search/filter, open bars first, three price categories, hours and deals. Recommendation failures cannot remove directory.
- [x] Four-item navigation and Settings links; preserve calendar.
- [x] Typecheck, lint, production build, synthetic-data behavior checks, independent review; source checkpoint and toolbox synchronization.

## Review focus
Unknown hours must never imply open. Overnight closing and midnight are explicit tests. Missing migration must not break ordinary restaurant editing. Unknown prices cannot become zero. Existing calendar must remain intact.

## Execution decisions
Scoped executor workers own UI, pure helpers, and profile persistence independently. Parent integrates and verifies. User approved execution already; no redundant plan approval requested.
